# Harborlight Bank Customer-Service POC

This authenticated POC tests Harbor, a model-driven retail-bank assistant, in
Gradio/ZeroGPU and local Streamlit. It combines:

- a PEFT-adapted Granite 8.79B generator;
- a V6 hierarchical CPU router with seven heads;
- constrained joint decoding for coherent route decisions;
- action-guided generation that exposes at most one tool schema;
- bounded pending-task, policy-detour, and resume state;
- deterministic policy retrieval and nine fictional banking actions;
- exact result tables, response grounding, and developer diagnostics.

All profiles and records are fictional. The application cannot access a real
bank or perform a real transaction.

## Request Flow

```text
customer turn + recent conversation + trusted prior dialogue state
  -> V6 seven-head CPU cross-encoder
  -> constrained joint domain/lane/family/intent/action/entity tuple
  -> relation thresholds for context, repair, topic shift, clarification, resume
  -> out_of_domain: fixed scope response; no Granite pass
  -> policy: retrieve evidence; Granite gets no tools
  -> execute_tool: Granite gets one intent-compatible schema and must call it once
     -> one bounded retry if the first pass emits prose
     -> grounded-final pass receives the result and no tools
  -> clarify/converse/uncertain: Granite gets no tools
  -> validate and execute model-selected arguments against fictional state
  -> exact table or grounded Granite response
```

The router never supplies tool arguments. It narrows the tool space to one
schema only when the decoded action is executable and the entity state is
usable. Granite derives arguments from conversation history. The harness
requires exactly one call before execution and rejects any repeat call after
the result, preventing duplicate routed mutations.

## Supported Actions

```text
list_accounts        list_cards          list_service_cases
list_transactions    list_transfers      freeze_card
replace_card         dispute_transaction cancel_transfer
```

Example model output:

```text
<tool_call>{"name":"list_transactions","arguments":{"limit":5}}</tool_call>
```

The harness validates the tagged JSON and schema, executes it against the
authenticated session's fictional data, and correlates the result with the
next Granite pass.

## Multi-Turn Behavior

The router reads up to three recent visible exchanges plus bounded pre-turn
state. Granite receives a larger token-budgeted conversation. The state
machine can preserve one servicing task through a policy question and restore
its original exchange when the customer asks to continue.

An explicit new intent replaces stale state. An ambiguous or missing action
target produces a natural clarification with no tool. An ineligible target
also blocks tool exposure.

## Confirming Model Generation

Open **Technical details** in Gradio or **Experiment diagnostics** in
Streamlit. Model-authored turns record:

- model-pass labels and raw outputs;
- prompt/output SHA-256 and input-token counts;
- runtime/CUDA device;
- exact base, adapter, and router identities;
- router hierarchy, action, entity state, and constraint diagnostics;
- exposed action schema, calls, results, or policy source IDs.

A turn with zero model passes was not generated by Granite. This is expected
for OOD, classifier failure, and policy no-match paths.

## Static POC Authentication

Both apps accept exactly:

```text
alex.demo
maya.demo
```

Set passwords of at least 12 characters:

```bash
export DEMO_AUTH_JSON='{"alex.demo":"replace-with-strong-value-1","maya.demo":"replace-with-strong-value-2"}'
```

Authentication selects a fictional profile and isolates session state. It is
not a production security design.

## Hugging Face Gradio/ZeroGPU

The queued model turn runs inside:

```python
@spaces.GPU(size="large", duration=90)
```

An authenticated chat smoke test verifies ZeroGPU worker entry, model
generation, and device metadata. The queue uses concurrency one for this
low-traffic POC. A separate decorated GPU probe is intentionally avoided so
ZeroGPU maintains a single warm-worker pool for inference.

Plan deployment:

```bash
ADAPTER_REVISION=cc95e446af2b5e1d8d9df2751a8192613ad386e3
ROUTER_REVISION=36920330d2502dfcf4d60572eadf1e3e71cd23fa

PYTHONPATH=src uv run python scripts/retail_bank/deploy_zero_gpu_space.py \
  --space-id spkc83/retail-bank-servicing-poc \
  --model-id spkc83/retail-bank-servicing-agent-9b-peft \
  --model-revision "$ADAPTER_REVISION" \
  --base-model-id spkc83/retail-bank-servicing-agent-9b \
  --base-model-revision 1d56824995aa1adecfe20f62ca42fb1c0c443817 \
  --adapter-id spkc83/retail-bank-servicing-agent-9b-peft \
  --adapter-revision "$ADAPTER_REVISION" \
  --model-dtype bf16 \
  --router-id spkc83/retail-bank-conversation-router \
  --router-revision "$ROUTER_REVISION"
```

The command prints a plan unless `--execute --allow-publish` is supplied. The
execution path uploads only allowlisted files and stores immutable pins as
Space variables. Treat the deployment as complete only after the Hub reports
`RUNNING` and an authenticated remote chat smoke test succeeds.

## Reset and Test

**Reset demo** or **Start over** clears visible/internal conversation, pending
task, policy detour, and fictional session mutations.

Run the POC suite without loading the 8.79B model or Hub router:

```bash
POC_SKIP_MODEL_LOAD=1 POC_SKIP_ROUTER_LOAD=1 \
  uv run pytest -q poc/retail-bank-customer-service-poc/tests
```

The skip flags are test-only.
